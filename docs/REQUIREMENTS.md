# Implementation against SRS 1.2

The source snapshot is `SRS-v1.2.txt`. This repository implements an initial test-gated release, not the complete expanded SRS. The project name is TensorFlow, while its Python namespace is tensorforge to avoid a library collision.

Implemented core: bounded CSV/JSONL/Parquet profiling, configuration proposal, schema validation, stable errors/warning acknowledgements, explicit approval, safe notebook generation, input hashes, output collision protection, independent embedded runtime, holdout/group/time splits, classical task metrics, generic predictions and restricted two-column sample submission mapping. Generated helpers are trusted source; user strings stay JSON data. No model execution occurs during generation. The local Streamlit UI exposes inspect/validate/generate and the coverage registry.

Core acceptance fixtures execute each of the nine verified adapter notebooks, including optional pair regression checks. Pipeline fitting occurs after splitting. Final outputs refit on all allowed training rows. Notebook execution rechecks row limits, IDs and boundary conditions on full input. The generator inspects only a bounded sample; it cannot guarantee every later execution succeeds. Exact overlap checks do not detect semantic leakage. Reused pair entities receive an explicit warning; connected-component splitting is not implemented.

Deliberate gaps relative to the full SRS: no universal task inference, no neural training/HPO, no arbitrary multi-stage composer, no presentation/chart report exporter, no comprehensive near-duplicate detector, no probability/score submission encoding, no retrieval submission adapter, no full-layout document preservation, no raw-offset NER, no topic-mixture NMF variant, and no asset-verified experimental model benchmarks. Planned scenarios refuse generation. Experimental adapters have real code but have not earned verified status through model execution fixtures. Status changes require tests and an explicit registry change.

The initial metric registry is intentionally small; official evaluators outside it need a trusted adapter and independent metric fixtures. The generation speed target has not been benchmarked on reference competition hardware. General visual-generation quality is not established by image shape/file checks. Optional pretrained models require provenance records; unknown pretraining overlap cannot be audited automatically. Competition eligibility remains pending for all catalog entries.

Architecture: `data.py` performs bounded reading/profiling; `config.py` validates and gates decisions; `registry.py` declares coverage; `generator.py` writes bundles and explicitly executes them only through verify; `templates/runtime.py` is embedded in notebooks; `ui.py` provides a local interface. Static templates avoid data-to-code interpolation. New tasks require registry/schema/runtime/fixture additions; the runtime dispatcher is intentionally explicit in this initial release.
